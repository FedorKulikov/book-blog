# Checklist публикации политики конфиденциальности

Политика публикуется только после подтверждения владельцем и профильным юристом.

## Оператор и контакты
- [ ] Подтвердить лицо/организацию — оператора обработки.
- [ ] Указать полное наименование/ФИО, форму, страну, адрес и регистрационные сведения.
- [ ] Создать официальный privacy email и проверить доступ к нему.
- [ ] Указать ответственное лицо и действующий канал запросов.
- [ ] Проверить применимость статьи 10(2) 149-ФЗ и разместить достоверные сведения о владельце сайта, включая наименование, место нахождения, адрес и email для заявлений по статье 15.7, если норма применима.
- [ ] Создать публичный канал privacy-запросов, доступный без входа в аккаунт; не использовать авторизационно-зависимый `/support` как единственный способ обращения.

## География и правовые основания
- [ ] Зафиксировать страны аудитории и возрастную политику.
- [ ] Проверить применимость 152-ФЗ и GDPR.
- [ ] Принять документированное решение по Supabase Frankfurt и локализации.
- [ ] Проверить статус уведомления по статье 22 152-ФЗ, если применимо.
- [ ] Для трансграничной передачи проверить статью 12 и нужные уведомления/оценки.
- [ ] Отдельно оценить использование Supabase Frankfurt с учётом статьи 18(5) 152-ФЗ и целевых категорий пользователей; сама публикация политики или получение согласия не заменяют требования локализации.
- [ ] Проверить обязанность уведомления Роскомнадзора по статье 22 и наличие/содержание уведомления, если применимо.

## Фактическая карта обработки
- [ ] Подтвердить Supabase Auth/DB/Storage регионы и договор.
- [ ] Подтвердить Layero runtime, логи и сроки хранения.
- [ ] Подтвердить Backblaze B2 endpoint/region, lifecycle и срок хранения.
- [ ] Подтвердить GitHub Actions log/artifact retention и права.
- [ ] Проверить, задан ли NEXT_PUBLIC_YANDEX_METRIKA_ID в production.
- [ ] Проверить Webvisor и маскирование полей/чатов; текущий код main задаёт `webvisor:false`.
- [ ] Проверить, задан ли `NEXT_PUBLIC_YANDEX_METRIKA_ID`: в текущем main счётчик автоматически запускается при наличии ID, отдельного баннера/consent-gate нет.
- [ ] Не описывать Метрику как включаемую только после согласия, пока код и production не обеспечивают такой сценарий.
- [ ] Если согласие на обработку персональных данных используется как правовое основание, оформить его отдельным действием и отдельно фиксировать доказательство согласия; не объединять с принятием правил или подтверждением ознакомления с политикой (ст. 9 ч. 1 152-ФЗ).
- [ ] Resend считать обработчиком только после запуска и проверки условий обработки.

## Цели, основания и права
- [ ] Для каждой цели зафиксировать данные, субъектов, основание и срок.
- [ ] Утвердить сроки для аккаунтов, публикаций, комментариев, сообщений, тикетов, логов и backup.
- [ ] Утвердить реальную процедуру удаления аккаунта и связанных данных.
- [ ] Утвердить удаление из резервных копий.
- [ ] Утвердить порядок доступа, исправления, удаления, отзыва согласия и жалоб.
- [ ] Отдельно оформить и фиксировать согласие там, где оно является основанием и требуется законом.

## Выпуск
- [ ] Юрист сверил финальную редакцию с production-настройками и договорами.
- [ ] Утвердить версию и дату вступления в силу.
- [ ] Опубликовать документ на /privacy.
- [ ] Добавить ссылку рядом с формами сбора данных, включая регистрацию.
- [ ] Разделить принятие правил сообщества/пользовательских условий и отдельное согласие на обработку персональных данных, если согласие выбрано применимым основанием; не использовать комбинированный чекбокс.
- [ ] Добавить ссылку в навигацию/подвал.
- [ ] Проверить интерфейс и доказательство отдельного согласия, если применимо.
